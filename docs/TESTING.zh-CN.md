# 验证与游戏内回归

自动化测试不能代替实际 SugarCube、ModLoader 加载顺序和完整事件测试。

## 自动化

1. `node --test tests/runtime.test.cjs`：运行时、事件注册、旧标记清理、身份限制、真实记录保持。
2. `python -m unittest discover -s tests -v`：条件语义、错误即停止、合成导出构建、历史参考还原。
3. 设置 `DOL_EXPORT` 后再运行 Python 测试：对本机实际导出包完整构建，检查宏结构、真实记录保留及 JavaScript 语法。

## 游戏内（尚待用户实测）

用独立存档副本，不覆盖主存档。

- 加载日志中本项目 25 条 Twee 规则、2 条 JS 规则全部成功；不要同时加载旧版。
- 失贞前后记录：真实贞洁字段、天使形态、angelbuild、fallenangel、纯洁、神殿誓约、brokenVowCount。
- 触发失贞：真实经历应正常记录，天使不因该宏堕落，相关路径不累计破誓，也不触发一次性 -50。
- 检查其他行为／事件仍能正常影响纯洁；不要把最终纯洁变化直接等同于某一个惩罚。
- 新的一天仍有 +2 加项，上限可达 1000；有其他属性 MOD 时按其设置核对最终值。
- 用已经失贞但其他条件齐备的存档进行神殿各阶段检查。
- 悉尼双人检查：玩家可豁免；悉尼自己的誓约失效仍应失败。
- 核对贞操带相关身体条件、可见腹部和其他资格条件未被绕过。
- 布莱尔／地下场所：只检验原范围中的资格与检查，不假设最终结算或后续状态会被重置。
- 艾弗里对应事件仍需神殿誓约与其他前置；成人用品店特殊遭遇并非安全／收益保证。
- 保存再加载、重启游戏、跨页跳转、载入旧存档后保护仍可使用。
- 禁用并重启后资格豁免消失；确认真实经历一直保持不变。誓约已恢复的存档值不会回滚。

若有失败，提供新的导出包和 `ModLoaderLog.txt`；请勿将包含完整游戏代码或存档的包提交到公开仓库。
